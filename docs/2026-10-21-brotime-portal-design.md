# 兄弟時光活動入口網站：設計文件

2026-10-21｜狀態：草稿，待使用者確認

## 1. 為什麼要做

「兄弟時光」是 2027 年創價班的年度活動企劃。企劃簡報（`~/code/sokahan-propalsal-2026/兄弟時光/兄弟時光_2027年度企劃簡報_修訂版.pdf`）訂了六項活動設計原則，其中第六項是：

> 工作人員拿來就能辦：下載 → 看 15 分鐘 → 準備簡單物品 → 開始。
> 自問：工作人員能不能在 30 分鐘內理解怎麼辦？

目前每個活動有兩種材料：

- **文字企劃案**（docx）：給審核用的正式文件，對工作人員來說太長。
- **「一分鐘看懂」手機圖卡**：每個活動 10 張，方向對了，但張數還是太多。工作人員最想知道的三件事分散在其中五張，要自己拼起來。

這個網站要取代「一分鐘看懂」，成為工作人員辦活動時唯一需要打開的東西。文字企劃案照舊留著當正式文件，網站只放連結。

用產品的角度來看，這是工作人員的 onboarding（從第一次打開，到第一次把活動辦成）和 retention（辦完下個月還想再辦）。簡報的成功指標二「工作人員辦完活動，自己也有感動」被列為最重要，其實就是 retention 指標。

## 2. 誰在用、什麼時候用

主要使用者是**各圈區的工作人員**，會遇到兩個時刻：

1. **區會開完後**：開始想下個月要辦兄弟時光。從 16 個活動裡挑一個適合區內夥伴的，再搞懂三件事：要準備什麼、60 分鐘怎麼過、故事卡和話題卡在哪一步用。
2. **活動當天**：在現場用手機一步一步帶活動。

工作人員多半從 LINE 群組點連結進來，也就是用 LINE 內建瀏覽器打開。

## 3. 目標、非目標、反目標

**目標**

- 工作人員 15 分鐘內看完一個活動，30 分鐘內知道怎麼辦。
- 從 16 個活動裡挑出適合自己區的，不必讀完全部。
- 第一次主持的人，當天照著手機也能辦完。

**第一版不做**

- 登入、報名、問卷系統、活動回報表、統計後台（見第 9 節「之後的路」）。
- 編輯介面：內容由企劃室（使用者本人）維護資料檔。

**反目標：出現以下情況，就算功能都做出來也算失敗**

- 看完一個活動要超過 15 分鐘，或要在好幾個檔案之間對照。
- 工作人員要自己印東西。卡片在網站上，問卷在線上填。
- 整場大家都低頭看手機。簡報「給手機給不了的東西」要的是面對面，所以只有念故事那一步請大家看自己的手機；話題卡只用主持人一支手機。
- 在山上、溪邊沒訊號時，當天模式打不開。
- 長得像公文或後台系統。
- 讓人覺得一定要照稿念、一定要跑完每一步。簡報原則是「冷場沒關係、不必跑完、不必每人發言」。

## 4. 網站結構

三個畫面，同一個網址：

```
入口（挑活動） → 活動頁（事前看） → 當天模式（現場跟著做）
```

草圖都在 `docs/mockups/`。這些是 HTML 片段，當初透過腦力激盪用的預覽伺服器顯示，圖片路徑寫成 `/files/…`；直接用瀏覽器開，排版和圖片會跑掉，但內容看得出來。原始檔在 `~/code/sokahan-propalsal-2026/.superpowers/brainstorm/65332-1792547965/content/`。

- `entry-options.html`：入口。使用者決定兩種形式合在一起，最上面放問答，下面放活動牆。
- `before-and-during-v2.html`：活動頁和當天模式，使用者已確認。
- `one-page-formats.html`：早期比較的三種一頁形式。使用者選了「一張流程圖」當活動頁、「現場跟著做」當當天模式。「食譜卡」沒有採用。

草圖裡的「說這句就好」台詞都是示意，正式內容要從企劃案取。

### 4.1 入口

- **最上面：「幫我挑」按鈕。** 一次問一題，共 4 題，最後推薦 3 個活動並寫出推薦原因，例如「會帶小孩・週末白天・下雨可改親子館」。
  1. 這次會有人帶小孩嗎？
  2. 區裡的夥伴什麼時候比較有空？選項：週末白天（週休二日）、平日下班後、一大早（上班前或下田前）、時間不固定（排休、輪班）。
  3. 想在室內還是戶外？戶外遇雨可能延期。
  4. 大家有共同興趣嗎？選項：吃、動、聊、玩、手作、沒特別。
- **下面：16 個活動的活動牆。** 上方有篩選按鈕，用的是同樣的條件：帶小孩、室內／戶外／下雨也能辦、有空的時段、共同興趣。不符合的活動變淡，不是隱藏。每張卡顯示活動名稱、一句話介紹、標籤，以及雨天標示（下雨也能辦／雨天改地點／雨天延期）。
- **還沒做好的活動也放上去**，變灰、標「準備中」（使用者決定）。點進去只有一句簡介。（我的決定）
- 「幫我挑」只推薦已完成的活動。（我的決定）

### 4.2 活動頁（事前看）

一個活動一頁，手機上從上滑到下，依序是：

1. **標題區**：活動名稱、一句話、三個數字（人數、時間、地點）。
2. **要準備**，分三塊：
   - **企劃室提供**：標題就寫「企劃室提供」（使用者指定的字）。故事卡和話題卡改放在網站上，不做實體卡片（使用者決定），所以這裡寫成「故事卡：在網站上，念故事時分享到群組」「話題卡：在網站上，主持人用手機帶大家抽」。只有桌遊之夜的桌遊和題卡還是實體的。
   - **你要做的**：附時間點，例如「3–4 週前：訂位、在群組邀約並私訊久未參加的夥伴」「前一天：提醒時間地點」。內容從各活動的企劃案和「一分鐘看懂」裡「辦之前做三件事」那張取。
   - **問卷**：線上填，活動最後掃 QR code，不用印。
3. **60 分鐘這樣過**：時間軸。每一步有時段、名稱、一句「說這句就好」。用到卡片的步驟，旁邊直接放卡片縮圖。
4. **「開始活動」大按鈕**：進入當天模式。
5. **最底下收合的三塊**（我的決定，簡報的「完整活動包」有列這幾樣）：「第一次主持記得五件事」「想多留 30 分鐘（選配）」「完整企劃案（下載 docx 或 PDF）」。
6. 戶外活動加一行「下雨怎麼辦」。

### 4.3 當天模式（現場跟著做）

- **出發前確認**：打勾清單，例如場地訂好了、手機有電也連得上網路，然後按「開始活動」。
- **一次只顯示一步**：大字時段、這一步做什麼、說這句就好。上方有進度條，例如「第 2 步，共 5 步」。
- **念故事的那一步**（使用者決定）：主持人按「分享故事卡」，叫出手機內建的分享選單（LINE 群組、AirDrop、複製連結都在裡面），大家在自己的手機上一起看。同一個畫面放這張卡片頁的 QR code，不在群組裡的新朋友掃主持人的手機就能打開，不用 AirDrop，Android 手機也能用。（QR code 是我的決定）瀏覽器不支援內建分享選單時，改顯示「分享到 LINE」和「複製連結」兩顆按鈕。
- **聊天用話題卡的那一步**（使用者決定）：主持人用一支手機帶大家抽。畫面一次顯示一張大卡，按「換一張」隨機抽下一張，抽過的不重複，整組抽完再從頭來。話題卡有分類的（例如早午餐會的前菜、主餐、飯後咖啡），上方可以切換分類。
- **沒訊號時**：分享和掃 QR code 都要網路。在山上這類沒訊號的地方，主持人直接用手機念故事卡給大家聽，畫面上要有一句提醒。
- **倒數計時**照每一步自己的時間走，不會自動跳到下一步，由主持人按「下一步」。超時就顯示一句安慰的話，像「超過幾分鐘沒關係，聊開了就讓大家聊」，不要用紅色警告。（我的決定）
- **最後一步**顯示參加者問卷的 QR code。結束後出現「填工作人員問卷」的連結。
- **沒訊號也能用**，因為有登山、露營、釣魚這類活動。（我的決定）做法：按下「開始活動」時，就把這場活動的所有步驟和卡片圖先載好，之後只要頁面沒關，沒訊號也能用。LINE 內建瀏覽器（尤其 iPhone）不一定支援離線快取，所以不能靠「打開過一次就會記住」。瀏覽器支援時再加離線快取當加分，只快取打開過的那個活動，不預先抓全部。活動頁上提醒一句：「要去沒訊號的地方，出發前在有訊號處先按『開始活動』。」
- 當天模式中螢幕不自動變暗，以支援的瀏覽器為準。（我的決定）
- 登山、露營等較長的活動，簡報說「正式程序嵌在其中」，所以步驟加起來不一定是 60 分鐘，時間軸和倒數照實際步驟走。

### 4.4 故事卡頁（給大家在自己手機上看）

- **每張故事卡有自己的網址**，例如 `a/brunch/cards/s1/`。這就是主持人分享出去、新朋友掃 QR code 打開的頁面。
- **頁面內容：**
  - 上面放卡片正面的圖。
  - 下面用橫排大字放故事全文，跟卡片上的文字一字不差。有些故事卡背面是直排小字，整張拍成圖在手機上讀不了。（我的決定）
  - 最後是出處。
- **貼到 LINE 的預覽**要有卡名和卡片圖。LINE 的預覽需要完整網址，所以網站設定要記住自己的網址，換網域時要一起改。預覽圖用 JPEG，因為 LINE 不一定認得 WebP。
- **話題卡不做個別頁面**，因為只在主持人的手機上用。（我的決定）
- **想印實體卡的區**：活動頁最底下的「完整企劃案」旁，留卡片 PDF 的下載連結。（我的決定）

**城市散步比較特別**：路線是每個區各一條環狀路線，停留點和故事卡因區而異。路線資料在 `城市散步/路線包工具/座標/*.json`，路線檢閱網站的資料在 `~/code/city-walk-review/data/routes.json`。所以活動頁要先讓工作人員選區，才能顯示那條路線。目前路線資料共 61 條，各區也都有路線包 PDF（`城市散步/路線包v10_各區PDF/`），所以不會有「這區沒路線」的情況。網站上城市散步仍是同一個活動頁，選區只是頁面裡的一個選項；區的代號要固定，因為之後的網址和統計會用到。

**城市散步的路線直接放進網站**（使用者決定），不只連到路線包 PDF：

- **活動頁**：選區之後，顯示那條路線的概要：集合點（含停車）、停留點清單、全長與大約時間，還有路線上會用到的故事卡縮圖。
- **當天模式**：每個停留點是一步。畫面上有停留點名稱、在這裡做什麼、說這句就好、這個停留點的故事卡，以及一顆「在 Google 地圖開啟」按鈕，導航到下一個停留點。
- **地圖只用 Google 地圖連結**，不在網站裡嵌入地圖，避免產生地圖 API 費用。路線檢閱網站有付費的 Maps API 金鑰，金鑰限定那個網站使用，這裡不要沿用。
- **路線還在檢閱中**，透過路線檢閱網站收意見、修改。入口網站的路線要跟檢閱網站從同一份來源資料產生，路線改了兩邊一起更新，不要另外手抄一份。產生檢閱網站資料的程式是 `plan-builder/build_route_review_site.py`。
- 61 條路線對 58 區：如果某區有不只一條，就讓工作人員在那區的路線裡再選一條。

**準備中的 8 個**：桌遊之夜、新春拜年團、田園烤肉會、家族辦桌拜年、農事體驗日、釣魚聊天會、師傅手藝教室、巷口泡茶會。農事、釣魚、手藝在 `plan-builder` 有半成品草稿。

**時程提醒**：簡報第一階段建議 1 月辦遊戲互動型（對應桌遊之夜）、2 月辦新春拜年（對應新春拜年團或家族辦桌拜年），這三個目前都還在準備中。月份主題只是建議，各圈區可以自由選，但上線時要知道有這個落差。

## 6. 內容從哪裡來

- **流程、準備清單、第一次主持、30 分鐘選配**：各活動最新版企劃案 docx。`plan-builder/build_<活動>_lazy_pack_v1.py` 裡已經有結構化的資料（像 `SCHEDULE`），可以當起點。各活動「一分鐘看懂」的最新版：爸爸帶娃日 v1、城市散步 v4，其他都是 v3。後面幾版大多只改外觀，內容以企劃案為準。
- **卡片圖**：各活動資料夾裡的故事卡、話題卡 PDF，轉成網頁用的圖片。用一般閱讀版，例如 `故事卡_v1_報紙版.pdf`，不要用「雙面裁切版」「一次兩套」「不印底色」這些印刷用的拼版。卡片按種類對應到步驟：故事卡放在讀故事那一步，話題卡放在聊天那一步，照企劃案的流程決定。活動頁只放代表性的縮圖；當天模式點開後，可以左右滑看整套。（我的決定）
- **故事卡全文**：一字不差抄卡片上的字，優先從 `plan-builder` 裡產生故事卡的 HTML 取，再跟 PDF 核對。直排的 PDF 用工具抽出來，順序常會亂掉。
- **話題卡的分類**：照卡片上印的分類，例如前菜、主餐、飯後咖啡。
- **準備中活動的一句話**：用企劃簡報「都會版候選活動」「鄉鎮版候選活動」兩頁上的介紹。
- **問卷**：問卷由企劃室在網站以外另外做，這個專案不負責建表單。預設全部活動共用一份參加者問卷、一份工作人員問卷，表單裡再選活動名稱；資料檔可以替個別活動改成別的連結。連結還沒拿到之前，最後一步顯示「問卷連結準備中」。（我的決定）
- **「說這句就好」**：每一步一句，從企劃案的流程說明摘出來。企劃案裡沒有現成的句子，就照企劃案的意思寫一句，交給使用者確認。
- **《新・人間革命》與御書引文**：只用故事卡上已經有的文字，不要另寫新的引文或轉述。
  - 2026-10-22 使用者改了這條：企劃案裡要主持人念的段落（收尾的話、主持稿）照企劃案原文放進該步驟的 `readAloud`，連出處一起顯示，不要叫主持人去翻企劃案；故事全文、卡名、出處仍照故事卡一字不改。
- **活動標籤**（帶小孩、室內戶外、雨天、時段、興趣）：從企劃案描述推，整理成一張 16 個活動的標籤表，在做「幫我挑」之前先給使用者確認。開發時先用暫定值。
- **確認方式**：一個活動做好，就給使用者看那一頁的實際預覽，連同「說這句就好」整頁一起確認，不用逐句另外確認。確認後才把狀態從「準備中」改成「已完成」，所以可以一個活動一個活動陸續上線。（我的決定）

每個活動整理成一份資料檔，網站讀資料檔產生頁面。之後補上「準備中」的活動，只要新增一份資料檔加卡片圖。資料欄位至少要有：

- 代號（之後網址和統計都用它，定了就不要改）、名稱、一句話、狀態（已完成／準備中）
- 人數、時間、地點、都會版／鄉鎮版、活動版型（簡報的五大版型 A–E）
- 標籤：帶小孩、室內戶外、雨天處理方式、適合時段、興趣
- 企劃室提供的物品（名稱、數量）、你要做的事（事項、時間點）
- 步驟：時段、名稱、做什麼、說這句就好、用到的卡片
- 下雨怎麼辦、第一次主持五件事、30 分鐘選配、企劃案檔案
- 參加者問卷與工作人員問卷的連結

## 7. 外觀

- 沿用故事卡的紙感、暖色調。內頁標題和數字用粗黑體（Noto Sans TC 900），內文用黑體。
- 每一步一個分類色，時間軸、當天模式的進度條和標籤都用同一組顏色。顏色要拉得開，小字對比至少 4.5。這是使用者在「一分鐘看懂」改版時定下的原則。
- 手機優先。LINE 內建瀏覽器要能正常顯示和操作。
- 用詞講人話，不用「模組」「流程節點」這類詞。

## 8. 怎麼做、放在哪

- 純靜態網站，放 GitHub Pages，免費。跟現有的城市散步路線檢閱網站（`cades.github.io/city-walk-review`）一樣做法。（我的決定）
- 先用 github.io 網址。之後換成學會官網的子網域（例如 `bro.twsgi.org.tw`，免費，要請學會資訊單位開）或 `brotime.tw`（一年約 NT$720–999），換網址不影響內容。網站設定要記一個完整網址，只給 LINE 預覽和分享連結用，換網域時改這一個地方就好。
- 技術選擇（框架、怎麼做離線快取）交給實作的人，原則是越簡單越好、使用者一個人維護得動。
- **上線時間**：假設要在 2026 年 12 月區會前上線，因為 12 月區會就要挑 1 月的活動。（我的假設）網站本身不受活動數量影響，準備中的活動做完一個就上一個。

## 9. 之後的路（第一版不做，但不要擋路）

使用者打算之後以 Google 登入為基礎，把**報名、問卷、活動回報表**整合進來。城市散步路線檢閱網站已經有一套可以參考的做法：Google 登入、Apps Script 網頁應用程式、Google 試算表。

第一版要先顧好的：

- 活動代號和網址結構定了就不改，之後報名、回報都會掛在上面。
- 問卷連結現在先寫在資料檔裡，之後換成網站內建的表單時，只要改資料檔。
- 用 Google 登入時，LINE 內建瀏覽器不能登入，連結要加 `?openExternalBrowser=1` 改用外部瀏覽器開。

之後可以追蹤的指標：哪些活動常被挑、同一區連續辦了幾個月（工作人員 retention）、參加者有沒有再來。

## 10. 交給實作的人決定的

- 框架與建置工具、資料檔格式、離線快取的做法。
- 「幫我挑」的推薦邏輯細節（例如條件怎麼加權），原則是推薦理由要能用一句話講出來。
- 卡片圖的解析度與壓縮方式。

## 11. 我替使用者先定的預設（請確認）

- 「準備中」的活動點進去只有一句簡介。
- 「幫我挑」只推薦已完成的活動。
- 活動頁最底下收合「第一次主持記得五件事」「想多留 30 分鐘」「完整企劃案」。
- 當天模式不自動跳下一步，超時不顯示警告。
- 當天模式打開過一次後可以離線使用，螢幕不自動變暗。
- 放 GitHub Pages、先用 github.io 網址。
- 按「開始活動」時先載好整場內容，不依賴瀏覽器的離線快取。
- 卡片圖用一般閱讀版 PDF 轉；當天模式點開卡片可以滑看整套。
- 問卷全部活動共用兩份（參加者、工作人員），可以替個別活動另設連結；這個專案不做表單。
- 每個活動做好給使用者看整頁預覽，確認後才從「準備中」改成「已完成」。
- 目標在 2026 年 12 月區會前上線。
- 念故事那一步除了分享按鈕，也放卡片頁的 QR code 給新朋友掃。
- 故事卡頁用橫排大字放全文；話題卡不做個別頁面。
- 想印實體卡的區，可以從活動頁下載卡片 PDF。
