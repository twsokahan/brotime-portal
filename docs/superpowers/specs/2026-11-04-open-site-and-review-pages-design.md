# 網站全面開放、登入只留給問卷結果：設計文件

2026-11-04｜狀態：使用者在對話裡逐段看過模擬圖並同意，已經過一輪實作者角度的審閱，待使用者看過這份文件。接在 `2026-11-03-login-and-district-stats-design.md` 之後，推翻其中「只限名單上的人」的部分。

## 1. 為什麼要改

2026-11-03 的設計是整個網站只給名單上的人用（創價班通訊錄、男子部幹部名單、補充名單），登入程式都寫好了，在分支 `task11-go-live` 還沒上線。

2026-11-04 使用者決定：**兄弟時光網站開放給所有人用，不再限通訊錄上的人**。登入只保留一個用途：區負責人和幹部看參加者問卷的結果。大部分人用不到，所以網站上完全不放入口，回顧頁的網址只傳到幹部群組（使用者原話：「一般人完全不需要看到」）。

同一天使用者也說「每一場的回顧」那頁很醜（截圖是還沒有回覆時的空白狀態：標題、「哪一區」下拉、一句說明、兩個連結，看起來像沒做完），所以趁這次一起改版。

## 2. 目標、非目標、反目標

**目標**

- 首頁、看全部、20 個活動頁、一番賞、故事卡：任何人打開就能看，不用登入，也不載入任何登入程式。
- 區負責人和幹部打開回顧頁網址，用 Google 登入一次，看得到自己範圍內每一場的問卷結果，以及「你們區的人想約」。
- 回顧頁在還沒有回覆時，看起來是刻意設計的：說清楚回覆怎麼來，放一張範例卡讓人知道之後會長怎樣。

**非目標**

- 改通訊錄、幹部名單的讀法或權限範圍。看得到哪幾區，照 2026-11-03 的規則不變。補充名單拿掉（第 7 節）。
- 在網站任何地方放回顧頁的入口，包括首頁頁尾。
- 給不在名單上的人做簡易版頁面（2026-11-04 曾討論過「20 種故事卡清單」，網站全面開放後就不需要了，不做）。

**反目標：出現以下情況就算失敗**

- 一般人在首頁、活動頁看到任何跟登入、問卷結果、幹部有關的字或按鈕。
- 名單裡的信箱出現在網頁、前端程式或 repo 裡（沿用 2026-11-03 的反目標）。
- 當天模式因為這次改動，在沒訊號時打不開（活動頁拿掉登入後本來就不受影響，只要別多加網路請求）。

## 3. 哪些頁要登入

| 頁面 | 要登入？ |
|---|---|
| 首頁 `/`、看全部 `all/`、活動頁 `a/<id>/`、一番賞、故事卡、新手小抄、隱私權說明 | 不用，也不載入 `signin.js` |
| 每一場的回顧 `stats/`、這一場的回顧 `stats/session/` | 要，照現在的登入牆 |
| 加一位主持人 `hosts/` | **拿掉這一頁**。它原本是讓區負責人把主持人加進名單、讓主持人能登入看企劃；現在主持人不用登入，加進去也看不到問卷結果。Apps Script 的加主持人 API 和補充名單也一起刪掉（第 7 節）。 |

回顧頁兩頁加 `<meta name="robots" content="noindex">`，免得被搜尋引擎收錄（我決定的）。

首頁原本登入後才出現的兩樣東西都搬走：

- 「你們區的人想約」從首頁搬進回顧頁（使用者決定）。首頁不再有 `.district-wants`、`district-wants.js`。
- 首頁頁尾（「看每一場的回顧 →」＋「已用 xxx 登入・登出」）拿掉。「已用 xxx 登入・登出」搬到回顧頁兩頁的最下面，樣式沿用這個分支已經改好的文字按鈕（`.text-button`，跟連結同色、加底線，不是全站那種 44px 膠囊按鈕）。

## 4. 登入畫面的字（只出現在回顧頁）

開始畫面：

> **每一場的回顧**
> 這頁是給區負責人和幹部看參加者問卷結果的。請用 Gmail 登入。
> ［Google 登入按鈕］
> （在 LINE 裡的提醒、錯誤訊息照舊）

不在名單上：

> **這個帳號看不到問卷結果**
> 你登入的信箱是
> xxx@gmail.com
> 你是區負責人或幹部的話，請把上面這個信箱傳給你的圈負責人。
> ［複製這個信箱］［換一個 Google 帳號］
> ← 回到首頁

原本最下面「只是想看故事卡？主持人分享給你的故事卡連結，不用登入就能看。」拿掉（網站已經全部開放）。以上字句是我擬的，使用者還沒逐字看過；網站文案不提「企劃室」（使用者先前的規則）。

看不到任何一區的帳號，Apps Script 直接當成不在名單上（第 7 節），前端不必另外處理「登入了卻什麼都看不到」。

## 5. 每一場的回顧（`stats/`）

使用者從兩個方向裡選了「一場一張回顧卡」：每一場一張小卡，不用點進去也看得出那一場辦得怎樣。

```
中和區的回顧                      ← 標題
共 3 場、12 份參加者問卷           ← 一行灰字（照目前篩選的範圍算）
［哪一區 ▾］                       ← 看得到不只一區時才有，只列有場次的區

┌ 你們區的人想約 ──────────┐      ← 只有區、圈層級，而且有回覆時
│ 1. 露營星空夜・5 人        │
│ 2. 男人的廚房・4 人        │
│ 3. 來去打球啦・3 人        │
│ 根據最近 3 場、共 12 份問卷 │
└──────────────────┘

┌──────────────────┐
│ ▢封面  11/16 週六          │      ← 日期大字（900 粗），是這頁最搶眼的東西
│        男人的廚房 5 份問卷  │      ← 看得到多區時，這行加上區名
│ 有人認真聽他說話  ●●●●○   │
│ 跟人變熟了        ●●●○○   │
│ 下次還想來        ●●●●○   │
└──────────────────┘      ← 整張卡可以點，進「這一場的回顧」

已用 xxx@gmail.com 登入・登出
```

- **標題**：區層級「<區名>的回顧」、圈層級「<圈名>的回顧」、全部層級「全台的回顧」（我決定的）。
- **點**：一個點就是一個填問卷的人。深藍＝第一個選項（有／會），淺藍＝第二個（普通／看時間），空心＝第三個（沒有／不會）。小卡只放三題：認真聽、變熟、還想來；第三題「跟印象中的創價班比起來」只在這一場的頁面出現。小卡和這一場的頁面用同一套三種顏色（我決定的）。人多時點會換行。
- **封面**：用該活動在首頁卡片牆用的那張縮圖（`cards/<id>/...-thumb.webp`）。問卷上的活動名稱對不到網站上的活動時，不放圖、照樣顯示卡片。
- **排序**：新的在上面（Apps Script 已經這樣排）。
- **「哪一區」下拉**：選項只列有場次的區，加「全部」；有場次的區只有一個或沒有時不顯示下拉。選擇照舊記在 `?d=`。
- **還沒有回覆時**：

  ```
  中和區的回顧
  參加者問卷的結果，一場一張卡。

  還沒有問卷回覆。主持人用當天模式帶完一場，最後一步請大家掃問卷 QR，
  填完的那一場就會出現在這裡。

  ┌ ─ 範例 ─ ─ ─ ─ ─ ─ ─ ─┐       ← 虛線框、淡一點，明顯是範例
    ▢封面  11/16 週六
           男人的廚房 5 份問卷
    有人認真聽他說話  ●●●●○
    ...
  └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─┘

  已用 xxx@gmail.com 登入・登出
  ```

  範例卡固定用男人的廚房的封面和假數字，不可點。「你們區的人想約」在沒有回覆時整塊不顯示。

## 6. 這一場的回顧（`stats/session/?id=`）

```

        男人的廚房                  ← 可以點，到活動頁

●有  ●普通  ○沒有                  ← 圖例

●●●●●

下一次想參加哪一種
▢ 露營星空夜   ●●●
```

## 7. 一份回覆也顯示（Apps Script）

使用者 2026-11-04：「好像不需要顧慮『免得認出是誰填的』，就算只有一份也顯示好了。」

- 拿掉「少於 3 份不列」：每一場有幾份就顯示幾份的結果；「你們區的人想約」只要有回覆就列。
- 前端拿掉 `NOT_ENOUGH_TEXT`、`WANTS_NOT_ENOUGH_TEXT` 和對應的畫面。
- 改的是 `apps-script/responses.mjs`（`MIN_RESPONSES`、`enough`），要 `npm run build:apps-script`、`clasp push`、`clasp deploy -i <原部署 ID>`，網址才不會變。**先部署 Apps Script，再推前端**。新前端不能依賴 `enough` 欄位，舊前端遇到新 API 也照常顯示。

**哪些回覆算同一場（我決定的）**：參加者問卷沒有「活動日期」這一欄，`date` 是填問卷那天的台北日期，現在一場＝「填的日期｜區｜活動」。大部分人在當天模式最後一步就填，但門檻拿掉後，隔天才補填的一份會變成另一張「1 份問卷」的卡。所以分組改成：同一區、同一種活動，從那一場第一份回覆起算兩天內（同一天、隔天、後天）填的都算同一場，卡上的日期用第一份那天。同一區兩天內辦兩次同一種活動的情況幾乎不會有，接受合併。場次的 `id` 照舊用「日期｜區｜活動」，日期是第一份那天。

**新前端遇到舊 API（我決定的）**：萬一 Apps Script 部署沒成功，舊 API 對少於 3 份的場次不給 `answers`、`next`。前端遇到沒有 `answers` 的場次，小卡只顯示「N 份問卷」、不畫點；這一場的頁面只顯示標題那塊。不另寫說明文字。

**Apps Script 清掉用不到的部分**（使用者 2026-11-04：「用不到的部分也刪掉吧，不要留技術債」）：

- 加主持人的 API（列出、加、移除主持人）和它用到的試算表鎖。
- 補充名單：`parseSupplement`、`SUPPLEMENT_HEADERS`、`createSupplementSheet()`、`SUPPLEMENT_ID` 指令碼屬性（從必填清單拿掉）、`checkSetup()` 裡的補充名單那行。補充名單上的人本來就只拿到「看不到任何一區」，現在登入只為了看問卷結果，它已經沒有用途。
- 合併名單時，看不到任何一區的人（`NONE_SCOPE`）不放進名單，登入時就回「不在名單上」。`checkSetup()` 的「看不到統計 N 人」那一項跟著拿掉。
- 對應的測試一起改。
- Apps Script 專案設定裡已經存在的 `SUPPLEMENT_ID` 屬性、企劃室帳號 Drive 的「兄弟時光｜補充名單」試算表，程式不再讀，留著不會壞事；要不要刪由使用者決定（第 12 節）。

## 8. 隱私權說明頁

照新用途改三處（Google 正式發布規定要有這頁，所以保留）：

- 開頭：「這個網站用 Google 帳號登入，只為了確認你是辦兄弟時光的人。」→「這個網站只有『每一場的回顧』要用 Google 帳號登入，讓區負責人和幹部看參加者問卷的結果。」
- 「比對你的信箱在不在可以使用的名單上：創價班通訊錄、男子部幹部名單，和各區負責人加進來的主持人。」→「比對你的信箱在不在名單上：創價班通訊錄和男子部幹部名單。」
- 刪掉「區負責人加主持人時，會記下主持人的信箱、名字、區，以及是誰、哪一天加的。」

改完的字給使用者看過再上線（使用者先前看過舊版文字）。

## 9. 限制

- 照舊是 GitHub Pages 靜態網站，推 `main` 就由 GitHub Actions 測試、build、部署。repo 公開。
- 配色、字體沿用網站現有的（`--paper`、`--ink`、`--box`、`--line`、`--muted`、`--step4-text`，Noto Sans TC 400/700/900），新的顏色（淺藍點）也定成 CSS 變數。
- 卡片圖的浮水印規則不變（`npm test` 會檢查）。
- `npm test`、`npm run build`、`npm run build:apps-script` 都要過。

## 10. 實作方式（我決定的）

- **看不到的人**：只有一種畫面，就是共用登入面板 `signin.mjs` 的 `not-listed`，改字即可；這個面板現在只出現在回顧頁。`stats.js`、`stats-session.js` 裡處理 `level === 'none'` 的分支、`NO_STATS_TEXT` 都刪掉。
- **登出那行**：`account.js` 不再掛在首頁，改成回顧兩頁都載入。兩頁的 HTML 都放 `<footer class="account-foot" hidden>`，`account.js` 只負責畫「已用 xxx 登入・登出」（不再有「看每一場的回顧 →」那行）。
- **範例卡的封面**：build 時確認 `kitchen` 活動存在、而且有封面縮圖，找不到就讓 build 失敗，不要上線一張破圖。
- **加主持人頁**：前端的 `src/client/hosts.js`、`renderHostsMain`、`HOSTS_PATH`、相關 CSS 和測試一併刪掉；Apps Script 那邊見第 7 節。

## 11. 留給實作的人決定

- 回顧頁拿封面圖的方式（例如把現在的 `activity-ids` JSON 擴成「名稱 → id、封面縮圖」）。
- Apps Script 是把 `enough` 整個拿掉，還是門檻改 1。
- 範例卡、點、日期大字的確切尺寸與間距，照模擬圖的比例即可。
- 測試怎麼改：現在有測試檢查首頁的 `account-foot`、`district-wants`、各頁帶登入牆、`hosts/` 頁，都要跟著改。

## 12. 上線

1. Apps Script 改完先部署（第 7 節）。
2. 這個分支（`task11-go-live`，裡面已有打開登入的 `content/site.json`）快轉合併進 `main`、推上去，看 Actions 部署成功。
3. 使用者用手機測正式網址：
   - 首頁、活動頁、看全部打開就能看，沒有任何登入字樣；LINE 裡打開也一樣。
   - 在 LINE 裡打開回顧頁網址，會轉到手機瀏覽器，用 Google 登入。
   - 區負責人帳號看到自己區的回顧卡和「你們區的人想約」；全部層級看得到「哪一區」下拉。
   - 不在名單上的帳號看到「這個帳號看不到問卷結果」。
   - 重新整理不再問登入；按「登出」回到登入畫面。
4. 把回顧頁網址傳到幹部群組（使用者自己傳）。
5. 要不要刪 Apps Script 專案設定裡的 `SUPPLEMENT_ID` 屬性、企劃室 Drive 的「兄弟時光｜補充名單」試算表，問使用者。
