# 電子一番賞：設計文件

2026-10-22｜狀態：草稿，待使用者確認

## 1. 為什麼要做

新春唱題會（`new-year-daimoku`）有一段 25 分鐘的「新春一番賞」：企劃室提供登機證造型的刮刮卡（`public/files/new-year-daimoku-ichiban-kuji.pdf`，一套十張：A 賞 1、B 賞 2、C 賞 3、D 賞 4）和一張看板（`new-year-daimoku-ichiban-board.pdf`，寫獎品、抽一張劃一格、最後一張被抽走的人再多拿一份「最後賞」）。

實體刮刮卡要印、要剪、要刮，人數一多還要自己調張數。使用者希望多一個電子版：

- **各區自己決定**要用實體刮刮卡，還是電子一番賞。
- 電子版用撕的，比較有一番賞的感覺。
- 主持人只要填好準備了幾份 A 賞、幾份 B 賞……，就能用手機抽。
- 現場是**主持人的手機傳下去，每人選一張，撕開**。

## 2. 目標、非目標、反目標

**目標**

- 主持人在一支手機上填好各等級的份數（可順便填獎品名稱），按「開始抽」。
- 手機傳下去，每個人從一排登機證裡選一張，沿虛線撕下存根，看到自己抽到幾等賞。
- 上方隨時看得到每個等級還剩幾張（像實體看板）；撕過的登機證變淡並標上等級。
- 最後一張撕完，跳出「最後賞」。
- 不小心關掉頁面或重新整理，回來接著抽，撕過的不會重來。

**非目標（這一版不做）**

- 多支手機同步、每人用自己的手機抽（網站沒有後端）。
- 自訂等級名稱或多於 A～D 的等級、獎品照片、音效。
- 防作弊。這是朋友間的遊戲，結果存在這支手機上，懂技術的人看得到也無所謂。

**反目標（做了反而失敗）**

- 撕之前就能看出哪張是幾等賞（畫面上、長按、放大都不行）。
- 主持人要先讀說明才會用；設定畫面要一看就懂，預設值照實體版（1／2／3／4＋最後賞），不改也能直接開始。
- 撕的手感很假，或手指不靈活的人撕不開（一定要有按鈕可以代替）。

## 3. 誰在用、什麼時候用

- **主持人**：當天現場，在自己的手機上打開。可能是在當天模式走到「新春一番賞」那一步時，按連結打開；也可能事前在活動頁看到、先試一次。
- **抽的人**：在場每個人，兄弟、太太、孩子都可以抽（使用者 2026-10-22 確認）。拿到主持人的手機，選一張、撕開、交還或傳給下一位。很多人第一次用，沒有人教。

## 4. 使用者已經決定的

- 手機是主持人的那一支，傳下去；每人選一張，撕開。
- 第一版草圖（三個畫面：① 主持人填份數 ② 選一張 ③ 沿虛線撕下存根）使用者看過，說「設計沒問題」：
  - 登機證造型照實體刮刮卡：左邊深藍抬頭「新春一番賞 BOARDING PASS」、冬 ✈ 春、航班 2027／日期 新春／登機門 唱題會；右邊是紅色抬頭「SEAT」的存根，撕的就是這塊。
  - 等級顏色照實體看板：A 紅、B 深藍、C 藍、D 芥末黃、最後賞 近黑的深藍。
  - 每張登機證用座位號碼（01、02……）區分，看不出等級。
  - 撕完顯示等級和主持人填的獎品名稱（沒填就只顯示等級），再按「交給下一位」回到選位畫面。

## 5. 畫面與行為

### 5.1 設定（主持人）

- 四列：A、B、C、D，每列有份數（0～99，0 表示不用這個等級）和獎品名稱（選填）。最後一列是最後賞的獎品名稱（選填）；最後賞固定有，不算在張數裡。
- 預設份數取自活動資料的 `ichiban.grades`（新春唱題會是 A 1、B 2、C 3、D 4，跟實體版一樣）。
- 顯示「共 N 張」。N 為 0 或超過 100 時，「開始抽」不能按，旁邊說明原因（「至少要 1 張」「最多 100 張」）；輸入框不偷偷改使用者打的數字，只把 0～99 以外的值標成錯。
- 現場人數不固定：在場每個人都可以抽（兄弟、太太、孩子），主持人照人數填份數。
- 「開始抽」：照份數產生 N 張，隨機排進座位 01～N，存起來，進入選位畫面。

### 5.2 選位（傳下去的手機）

- 上方：看板，每個等級顯示剩幾張，加上「剩 X 張」。
- 下方：N 張小登機證，依座位排列。還沒撕的只看得到座位號碼；撕過的變淡，標上抽到的等級。
- 點一張還沒撕的，進入撕券畫面。

### 5.3 撕券

- 放大顯示選中的那張登機證。存根上只有「SEAT」和座位號碼，看不出等級。
- 手指按住存根往下拉：存根跟著手指沿虛線慢慢撕開；拉過一定距離放手就撕下來，不夠就彈回原位。
- 旁邊有一個「撕開」按鈕，按了直接撕開（給不方便拖曳的人，也支援鍵盤）。
- 撕下來後，顯示大大的等級（該等級的顏色）和獎品名稱。手機支援的話，撕下的瞬間輕震一下。
- 「交給下一位 →」回到選位畫面。
- 剛撕完的若是最後一張：顯示等級之後，接著出現「最後賞」：「你抽到最後一張！再多拿一份最後賞」（有填獎品就一起顯示）。之後選位畫面顯示「全部抽完了」。
- 系統設定為減少動態效果時，不做撕開的動畫，直接顯示結果。

### 5.4 存檔與重來

- 這一輪（份數、獎品名稱、每個座位的等級、哪些撕過、最後更新時間）存在這支手機上（localStorage，key 依活動區分：`ichiban:<活動 id>`），重新整理或關掉再開會接著抽。最後更新時間在「開始抽」和每次撕券時更新。
- 選位畫面有「重新開始」：按第一下變成「確定重來？」，再按一次才清掉，回到設定畫面，並預填上一輪的份數和獎品名稱。不用瀏覽器的確認視窗。
- 存檔的最後更新時間超過 24 小時，就當成上一場的：打開時回到設定畫面，預填上一輪的份數和獎品名稱。
- 存檔壞掉或格式不對，就當成沒有存檔，不能讓頁面壞掉；預填值不合法（例如總和超過 100）時，改用活動資料的預設份數。
- 選位畫面和登機證由瀏覽器端程式依存檔畫出來（張數要到執行時才知道）。還沒撕的座位，等級不能出現在畫面上的文字、元素屬性或樣式裡；撕開那一刻才放進畫面。存檔裡當然有每個座位的等級，這是接受的。

## 6. 放在網站的哪裡

- 新頁面 `a/<活動 id>/ichiban/`，只有活動資料裡有 `ichiban` 設定的活動才產生（目前只有新春唱題會）。頁面外殼沿用 `src/render/layout.mjs`，跟故事卡頁一樣有回到活動頁的連結；不出現在入口頁。
- 活動資料新增 `ichiban` 欄位：`{ "grades": { "A": 1, "B": 2, "C": 3, "D": 4 } }`，當作設定畫面的預設份數。資料驗證：A、B、C、D 四個都要有，各是 0～99 的整數，總和 1～100。
- 步驟新增選填欄位 `"tool": "ichiban"`，標出「打開電子一番賞」按鈕放在哪一步。資料驗證：值只能是 `"ichiban"`，而且只有活動有 `ichiban` 設定時才能用。新春唱題會的「新春一番賞」那一步加上它。
- 連結：
  - 活動頁：有 `ichiban` 設定的活動，由活動頁的版型自動在準備區（企劃室提供／印刷檔附近）放「電子一番賞（不用刮刮卡也能抽）」，不另外寫在資料裡。
  - 當天模式：有 `tool: "ichiban"` 的那一步，出現按鈕「打開電子一番賞」，用新分頁開，當天模式的進度不受影響。
- 這個頁面跟活動頁一起出現或不出現：活動在正式網站顯示為準備中時（包括 `review`），不產生這個頁面，活動頁也沒有連結；預覽版照常產生。判斷用跟活動頁同一個顯示狀態。
- 這是主持人用的頁面：在 LINE 裡打開時，沿用活動頁現有的做法（`src/render/leave-line.mjs`）改用手機瀏覽器開。跳不出 LINE 時頁面照樣能用，只是存檔留在 LINE 的瀏覽器裡；這是接受的。
- 新春唱題會的內容同步改：一番賞那一步、企劃室提供、內容筆記都寫明「實體刮刮卡或電子一番賞，各區自己決定」。

## 7. 怎麼做（照網站現有的做法）

- 純邏輯放 `src/lib/ichiban.mjs`（會原樣送到瀏覽器：不能 import `node:` 模組，只寫純函式）：照份數產生一輪、洗牌（亂數來源可以傳進來，測試才固定得住；瀏覽器用 `crypto.getRandomValues`）、撕某個座位、每等級剩幾張、是不是最後一張、存檔的讀寫與驗證。測試放 `tests/ichiban.test.mjs`。
- 頁面 HTML 由 `src/render/` 產生；瀏覽器端程式放 `src/client/ichiban.js`；樣式加在 `src/styles/site.css`。
- 撕開之前，等級不能出現在頁面的 HTML 或元素屬性裡，只在撕開那一刻才放進畫面。
- 網站零依賴，這次也不加任何套件。
- 字一律避開「活動」「舉辦」（`docs/wording-changes.md`）。

## 8. 交給實作的人決定的

- 撕開動畫的細節（存根旋轉的角度、掉落方式）、門檻距離、震動長度。
- 設定畫面份數的輸入方式（數字欄或加減按鈕），只要 320 寬的手機好按。
- 小登機證在選位畫面的排法（幾欄），只要 320 寬不橫向捲動、N 到 100 張也找得到。

## 9. 我替使用者先定的（請確認）

- 等級固定 A～D＋最後賞，份數可以是 0（不用那個等級）。
- 總張數上限 100。
- 存檔 24 小時沒動就當成上一場。
- 「重新開始」要按兩下確認。
- 用新分頁從當天模式打開電子一番賞。
- 資料怎麼表達：活動的 `ichiban` 預設份數、步驟的 `tool: "ichiban"`；活動頁的連結由版型自動放，不另外寫資料。
- 份數不合法時「開始抽」不能按並說明原因，不偷偷改數字。
- 頁面外殼沿用網站現有的版型，不放進入口頁。
